# GB-142 — Retried payments are booked twice
<!-- module: 1 · labels: bug, agent-ready -->

**Type:** Bug · **Priority:** High · **Epic:** Client money integrity
**Repository:** global-bank-account · **Reporter:** Payments Operations

## Description

Operations found three duplicate postings in the March payroll run. Each time, the upstream payroll
feed retried after a gateway timeout. The service accepted the retry as a new instruction. So it
wrote a second pair of ledger entries for the same payment.

The duplicates match the originals field for field. Only the posting id is different.

Today nothing in `PostingService.post` looks for an existing posting before it creates one.

## Acceptance criteria

1. Posting the same instruction twice gives **one** posting, not two.
2. The retried call still returns the posting id to the caller. It must not fail.
3. Payroll sends the same client reference again for instructions that are genuinely separate
   payments, not retries. Those must still be accepted. Decide what tells the two apart, and say
   in your summary which rule you chose.
4. New instructions behave exactly as they do today.
5. Covered by tests.

## Notes

Operations want this in the next release. The team talked about duplicate handling a while ago.
Check whether anything was written down before you design it.
