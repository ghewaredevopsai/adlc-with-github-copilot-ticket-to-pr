What you will be able to do after Module 1M1

The idea

  • This course is not about whether AI agents work. It is about what each request costs.
  • When the agent re-learns what your team already knows, you pay twice: in credits, and in wrong answers.

How we start

  • In Lab 1.1 you do one real ticket, with no preparation, and count what it took.
  • That number stays in metrics.md for two days.

Words used in this courseM1

AI and agent words

  • Model — the AI that writes the answer. Some are fast; some think harder.
  • Agent — Copilot in agent mode. It reads files, edits code and runs commands.
  • Prompt — what you type to the agent.
  • Turn — one prompt from you plus one reply.
  • Token — a small piece of text. Models read and bill in tokens.
  • Context window — everything the agent can see right now. A new chat starts empty.
  • Tool call — the agent uses a tool: reads a file, searches, runs a command. The tally counts only file reads and searches.
  • Hallucination — a made-up answer that looks real.

Course words

  • ADLC — the development lifecycle when AI agents write much of the code.
  • AI credits — how GitHub bills Copilot use.
  • Re-discovery tax — the cost of the agent re-learning facts your team already knows.
  • Tally sheet — metrics.md: six numbers for each measured run.
  • ADR — a short file that records one design decision.

Three kinds of task — name it before you choose anything4

Choosing the model — how unclear is it, and how bad is a mistake?4

Two kinds of model

  • Fast model — quick and cheap. Good when the answer is already known.
  • Reasoning model — slower, costs more. Thinks through hard choices.

The habit

  • Name the box before you send the request.
  • Split big tickets: one hard decision, then lots of simple work.
Unsure, so reaching for the strongest model? The ticket is unclear. Fix the ticket instead — Module 5.

Mode decides how much the agent may change4

The context window is a budget — and you are already spending it5

Before adding anything, ask

  • Needed on every request? → put it in a file.
  • Needed sometimes, and big? → fetch it with a tool call.
  • Needed only now? → put it in the chat.
This is the placement rule: chat, file, or tool call. Later modules use it all the time.

The placement rule — a file, the chat, or a tool call5

Long chats — when to compact, when to start a new one5

Good habit

  • Write decisions into a file — the spec, an ADR, the instructions. Then a new chat loses nothing.
  • Module 5 builds on this: the spec lasts; the chat does not.

Common mistakes

  • Thinking a long chat is a good thing.
  • Prompting harder when the chat is past its best.
Typing “ignore what I said earlier”? Start a new chat instead.

Interactive or delegated — where your attention goes6

Chat with it, or hand it off? Four checks, in order6

How to use it

  • Check the gates in order. Gate 1 fails most often.
  • One failure is enough. There is no average score.

It gets easier

  • Modules 2, 3 and 5 help you pass these gates.
  • A ticket that needs you today may be safe to hand off tomorrow.
Choosing interactive for an unclear ticket is the right call, not a weak one.

What Module 1 hands to the rest of the courseM1

Four questions before every request

  • What kind of task? Mechanical, reasoning, or review.
  • Which mode? Ask, Plan, or Agent.
  • What goes in the window? Chat, file, or tool call.
  • Interactive or hand off? Check the four gates.
Remember: the agent will not tell you what it did not know. That is why we measure.
